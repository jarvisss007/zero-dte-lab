## Firm Brain check — a NEW mechanism, not an incident
**A gate counted against a MOVING threshold re-judges frozen data.**
`session_count.py` admits a session if its row count is >= 86% of the *current*
full-session median. Adding sessions moves the median, so the bar moves under files
that never change. Measured today, exactly:

- 2026-08-31 stamp: median 11,339 rows -> bar **9,751**. `2026-08-10` (**9,765 rows**)
  was listed **usable AND admissible**.
- 2026-09-02 stamp: median 11,380 rows -> bar **9,786**. The same file, **byte-identical,
  mtime Aug 10, one commit in git**, is now a **stub**.

Nothing about 08-10 changed. The population behind it did. So progress toward the
60-session gate **is not monotone**: today reads 23 admissible, and a run of full
sessions next week can silently take one back. This is Firm Brain §6 applied to a
verdict rather than a value — the same session has two answers depending on when it is
asked — with §9's aggravating half inverted: §9 warns that a partial captured once is
frozen forever; this is the opposite failure, a settled artifact whose judgment never
settles.

**Proposed guard (for the council, not shipped unasked):** judge each session ONCE, at
first sight, against the threshold in force that day, and write `admitted_on`,
`rows` and `bar_at_admission` onto the session record. A session's verdict should be a
property of that session, not of the sessions that came after it.
